## Affected Pages/Routes
- `/` and `/static/index.html` — verify the landing and search application render untrusted filenames, camera IDs, errors, and live-event values as text rather than executable HTML.
- `/health/live` — verify AppSail can bind and return liveness while database, Redis, storage, and Qdrant are unavailable.
- `/health/ready` — verify each backing-service failure is named and returns HTTP 503, while all-ready returns HTTP 200.
- `/videos` — verify authorized listing and direct upload success, extension rejection, size limit, storage failure, and queue-dispatch recovery.
- `/videos/upload/*` — verify multipart initiation, owner/admin access, upload-key binding, part bounds, storage failures, successful completion, and dispatch recovery.
- `/search` — verify inline and explicit filters, empty results, authorization scope, model outage, vector-store outage, and reranker selection.
- `/videos/{video_id}/summarize` — verify successful summaries, invalid IDs, invalid backends, and unavailable model/provider responses.
- `/live/*` — verify authenticated registration/listing, secret-protected webhooks, JSON-safe broadcasts, unknown cameras, disconnect events, and websocket cleanup.
- `/events/track` — verify temporal clustering, cross-camera transitions, empty results, and search failures.
- MCP tools — verify search, summarize, camera listing, session cleanup, and downstream error propagation.

## Key Interactions to Verify
- Start the API with model hubs offline and all backing services unreachable; confirm the HTTP port binds before heavyweight model or dependency initialization.
- Upload a supported video, observe its database state advance from uploaded to processing, and confirm a broker failure leaves a recoverable `dispatch_failed` state.
- Complete multipart upload as the owner and as an admin; reject another investigator without mutating storage or database state.
- Send MediaMTX webhook payloads with quotes and markup in camera IDs; confirm broadcasts are valid JSON and browser rendering remains inert text.
- Search with camera, object, and time filters; open a returned clip and request a generated summary.

## Edge Cases
- Empty filename, unsupported/mixed-case extension, path-like filename, oversized streaming body, empty multipart parts, part 0, part 10001, wrong key, and expired upload ID.
- Database commit failure after storage succeeds, queue outage after upload succeeds, and duplicate multipart completion.
- Missing/wrong webhook secret, unknown stream path, disconnect before publish, malformed websocket data, and websocket client removal during broadcast.
- Zero-duration media, ffprobe failure, absent video/segment records, no audio track, per-frame model failure, retry exhaustion, and Qdrant upsert failure.
- Empty search result, missing timestamps/camera IDs, a single event, events exactly five seconds apart, and multiple camera transitions.

## Critical Paths
- AppSail container starts → Uvicorn binds `$PORT` → `/health/live` responds → background dependency initialization proceeds → `/health/ready` reflects real dependency state.
- Investigator authenticates → initiates multipart upload → uploads parts → completes storage upload → orchestration task is queued → segment records are created → vision/audio workers publish → video becomes indexed → search returns playable evidence.
- Media server sends authenticated webhook → source status is committed → JSON event is broadcast → browser displays escaped camera/status text.
- User searches evidence → authorization scope limits video IDs → semantic and lexical results fuse/rerank → clip URL and summary remain accessible only to authenticated users.
