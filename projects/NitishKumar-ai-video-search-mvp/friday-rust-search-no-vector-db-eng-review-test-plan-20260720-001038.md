## Affected Pages/Routes
- GET /search — core semantic search; verify camera:/after:/before:/object: inline filters still work and 503 appears (not 500) when the vector store is down
- POST /videos — upload with AND without camera_id; both must reach status=indexed and be searchable
- GET /videos/{id}/clip — unchanged, but verify clip URLs from search hits still play

## Key Interactions to Verify
- Upload sample video → poll status → search a phrase visible in the video → hit returns with plausible score and clip link
- Search with camera filter for a camera with few videos (selective filter) → still returns up to `limit` results
- Search with only `after:` (open-ended time range) → results at/after that time only
- Stop the helixdb container → search returns a 503 with "Vector search failed" message → restart container → search recovers

## Edge Cases
- Upload with no camera_id → video indexes; appears in unfiltered search; excluded when filtering by any camera
- Re-run/retry of an ingest task (kill worker mid-ingest, let Celery retry) → no duplicate hits for the same frame; vector count unchanged on second run
- Very short/corrupt video (0 sampled frames) → status becomes indexed with 0 vectors, WARN in worker logs, no crash
- Empty search results (nonsense query on empty corpus) → 200 with [], not an error

## Critical Paths
- Full e2e: docker compose up (all healthchecks green) → API boot succeeds (readiness probe verifies insert_frames/search_frames/delete_video_frames deployed) → upload → indexed → search → clip
- Parity fixture: identical query set against real HelixDB (make test-integration) and FakeHelixClient (pytest) produce identical rankings and same-direction scores
