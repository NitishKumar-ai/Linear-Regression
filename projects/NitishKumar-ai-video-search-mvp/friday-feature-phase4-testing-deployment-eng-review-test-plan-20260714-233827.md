## Affected Pages/Routes
- `/search` — RRF fusion merges visual + lexical results; test multi-modal queries
- `/videos/{video_id}/clip` — Unchanged but verify GPU-processed frames still produce valid clips
- New internal module: `api/rrf_engine.py` — Rank fusion logic
- New internal module: `workers/gpu_preprocessor.py` — GPU decode + preprocess pipeline
- New internal module: `api/event_graph.py` — Cross-camera event clustering and traversal

## Key Interactions to Verify
- Multi-modal search: query with both visual and audio terms returns fused results
- Audio-only search: query matching only transcripts returns transcript-sourced results
- Visual-only search: query with no transcript matches falls back to visual-only ranking
- GPU preprocessing: frames decoded via PyNvVideoCodec are equivalent to CPU-decoded frames
- CPU fallback: when CUDA unavailable, pipeline falls back to OpenCV without error
- Event clustering: adjacent frames from same camera grouped into single events
- Cross-camera tracking: search returns chronological timeline across multiple cameras

## Edge Cases
- Empty transcript table: RRF returns visual-only results without error
- Both modalities return zero results: search returns empty list, not 500
- Corrupt video frame: GPU decode fails, fallback to CPU, frame skipped gracefully
- Single-camera dataset: Event Graph returns events with no transition edges
- Disconnected graph: shortest_path returns "no path" without crash
- RRF with k=0: weight validation prevents division-by-zero
- GPU OOM: CUDA out-of-memory caught and logged, processing continues on CPU

## Critical Paths
- End-to-end: upload video → GPU ingest → search with multi-modal query → get clip
- RRF ranking correctness: known fixtures with controlled visual + lexical ranks → verify fusion order
- GPU memory: two concurrent ingestion tasks don't crash on shared GPU
