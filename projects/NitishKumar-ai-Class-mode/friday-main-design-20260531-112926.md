## Problem Statement

Indian coaching centers and private schools create assessments (MCQs, short-answer questions) manually. A teacher preparing a JEE/NEET test spends 30–90 minutes writing questions from scratch or searching the internet for existing ones. There is no digital tool for this in their workflow — no software, no subscription. It happens in Word docs, on paper, or from memory.

EduAI has already built AI tutoring, live classes, and a full LMS. But no real users have been acquired yet. The goal now is to find the narrowest wedge that a specific person would pay real money for — and validate AI willingness-to-pay before expanding the platform.

## Demand Evidence

- No paying users yet
- Manual workflows confirmed: target users do things without digital tools
- Target segment: India-based teacher/admin, private unaided schools and coaching centers
- The subagent's market sizing: ~300,000 owner-operated private schools in India, uniform buyer profile (owner/principal, decides in days, ₹3,000–8,000/month ceiling)

## Status Quo

Teachers write test questions manually: from memory, from textbooks, from internet searches. The process is time-consuming and repeated every week. Coaching centers (JEE/NEET prep) set multiple tests per week — this pain is felt most acutely there.

## Target User & Narrowest Wedge

**Target:** Owner or senior teacher at a JEE/NEET coaching center in India (urban, 50–500 students). Already uses WhatsApp and Google Drive. Not currently using any AI tool.

**Wedge:** AI-powered test generator. Teacher uploads a PDF (notes, textbook chapter) → AI generates N MCQs with answers → teacher copies to clipboard or shares directly with students.

**Pricing signal to test:** ₹10–20 per test generation, or ₹499/month for unlimited. Ask before building a payment flow.

## Constraints

- Existing codebase has Google Gemini 2.0 Flash integration — this is the AI engine to use
- Existing Express + PostgreSQL backend — reuse for API and user tracking
- No new infrastructure needed
- Must work on mobile (teachers use phones, not desktops)
- Time to first demo: 48 hours

## Premises

1. Indian coaching center teachers spend meaningful time creating assessments manually — agree
2. AI-generated MCQs from a PDF upload are high enough quality to be useful without heavy editing — **needs to be tested with real users**
3. Willingness to pay exists if quality is high — **the assumption to validate**
4. The test generator can be a standalone product before it becomes a feature inside EduAI — agree

## Approaches Considered

### Approach A: The WhatsApp Killer — strip everything
Build one thing: teacher posts homework → parents see it. Use existing Express + PostgreSQL. Cut all AI and infrastructure. Wedge = parent-teacher communication.
- Effort: S (2 days / CC: ~1 hour)
- Risk: Low
- Pros: Fastest to demo, zero AI dependency, viral (parents share link)
- Cons: Doesn't leverage existing Gemini investment, low moat, crowded space (ClassDojo etc)

### Approach B: The AI Test Generator (CHOSEN)
Teacher uploads PDF → Gemini generates MCQs → downloadable/shareable. Standalone tool, no login initially.
- Effort: M (1 week / CC: ~2 hours)
- Risk: Medium (AI output quality unknown until tested)
- Pros: Leverages existing Gemini, validates AI willingness-to-pay, clear before/after for the teacher
- Cons: PDF parsing quality is variable, requires teacher to trust AI output quality

### Approach C: The Platform Play — find a pilot school first
No code changes. Find ONE school owner for a 30-day free pilot. Let usage data reveal the sticky feature. Then charge for it.
- Effort: L (1 month of sales work)
- Risk: Low-code, high-time
- Pros: Data-driven, no build risk
- Cons: Slow, requires sales skills, platform may not be ready for real use

## Recommended Approach

**Approach B: AI Test Generator**

Build a stripped-down, standalone test generator that reuses the existing Gemini integration. The goal is not a polished product — it's a demo you can show to a coaching center owner by Monday.

**What to build (48 hours):**
- One-page React form: upload PDF + choose subject + choose number of questions
- Express endpoint: extract text from PDF (pdf-parse; reject uploads where extracted text < 500 chars with message "Please upload a text-based PDF, not a scanned image") → send to Gemini → return structured MCQ JSON
- Gemini prompt shape: `Given the following text, generate {N} multiple-choice questions with 4 options each. Mark the correct answer. Return a JSON array with fields: question, options (array of 4 strings), answer (index 0-3). Text: {extracted_text}`
- Gemini PDF input mode: extract text server-side via pdf-parse, send as plain text string (not the File API — the existing Express integration handles text strings only)
- Output: rendered MCQs on-screen + copy-all to clipboard (v0). PDF download is v1.
- No login for v0. Anonymous session tracking only (session_id + timestamp in Postgres, no user identity).
- Mobile-responsive

**What to skip:**
- Grading, student answers, LMS integration
- Multi-tenancy, workspaces, RBAC
- Payment flow (ask "would you pay ₹10 per test" verbally first)
- Cassandra, Daily.co, Whisper, SIS

**After the demo:**
Ask 5 coaching center owners: "Does this save you time? Would you pay ₹10/test or ₹499/month?" The answer to that question is worth more than 6 months of building.

## Open Questions

1. What's the quality of Gemini output for JEE/NEET-style MCQs from PDF input? (Test immediately with a real NCERT chapter)
2. What format do teachers want the output in? (PDF? Google Docs? WhatsApp share?)
3. Is the bottleneck question generation or answer key generation? (Answer keys might be more valuable)
4. What's the right pricing signal — per-test or monthly subscription?

## Success Criteria

1. 5 coaching center owners shown the demo within 7 days
2. At least 1 says "I would pay for this" — with a specific number
3. AI generates ≥15 usable MCQs (out of 20) from a standard NCERT chapter. "Usable" = no hallucinated answer keys, all 4 options grammatically complete, no repeated questions.
4. Demo time < 30 seconds: upload PDF → see questions

## Distribution Plan

- v0: Demo link shared via WhatsApp (how teachers actually share things in India)
- v1: Simple web app with URL, no app install
- Not on Play Store / App Store yet — web-first, mobile-responsive
- No CI/CD changes needed — deploy via existing GCP Cloud Run pipeline

## Dependencies

- Google Gemini 2.0 Flash API (already wired in)
- PDF parsing library (pdf-parse or pdfjs-dist — needs testing for quality)
- Existing Express + PostgreSQL backend
- Blocker: None — can start immediately
