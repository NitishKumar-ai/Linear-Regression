## Key Interactions to Verify
- Mark attendance happy path: select class (remembered), all-present, mark exceptions, save — persistent day-status line updates
- Save under no connectivity: entries queue, status shows "waiting to send (N)", survives page reload and app restart
- Reconnect sync: idempotent replay (no duplicate feature_usage rows, no duplicate notifications), status flips to synced-with-timestamp
- Conflict path: stale write returns per-row conflict payload (never silent success); conflict-review flow resolves student-by-student; resolution lands in audit_events atomically
- Term report generation with rich data, thin data (explicit named empty sections, denominators shown), and query failure (visible error, never blank-plausible)
- Report handover: printed A4 grayscale, aggregate-only (no student names)
- Vernacular switcher: wedge-screen keys incl. toasts/errors resolve to locale strings; switching language never discards unsaved marks

## Edge Cases
- Queued entry older than the 3-day backfill window → terminal "window-expired" state with escalation copy (not infinite retry, not silent drop)
- Auth expiry with queued marks → "sign in again — your marks are safe on this phone"; queue survives re-auth
- Hostile cross-tenant: principal of school A requests school B's term report by ID manipulation → 403; principal with NULL schoolCode → 403 fail-closed
- Admin-marked attendance carries school_code (regression: attendance.ts:115 property-name bug)
- metrics:weekly on an empty/new-school DB → honest zeros, no divide-by-zero on baseline week
- Double-save after sync → idempotent, no double-count, no second "saved" celebration
- Backup restore test restores into a scratch DB and asserts row counts (not just pg_dump exit 0)

## Critical Paths
- Teacher marks attendance offline at 8:50am, pockets phone, syncs at lunch — zero lost entries, honest status throughout
- Principal receives term report + paid-pilot offer in one sitting — every number on the page is true and sourced
