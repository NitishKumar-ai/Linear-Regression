## Affected Pages/Routes
- `POST /api/commitguard/scan` — trigger scan, validate auth + URL + concurrency
- `GET /api/commitguard/status/{job_id}` — poll scan progress
- `GET /api/commitguard/stream/{job_id}` — SSE live progress, job_id ownership check
- `GET /api/commitguard/findings/{job_id}` — findings list with all verdicts
- `CommitGuardPage.tsx` — URL input, progress bar, findings table

## Key Interactions to Verify
- Submit valid GitHub URL → job_id returned → SSE stream updates progress → findings appear
- Submit invalid URL (not https://github.com/) → 400 error message shown in UI
- Submit scan while another is running → 429 response → UI shows "scan in progress"
- E2B key missing → all findings return UNVERIFIABLE → UI shows findings with UNVERIFIABLE badge
- CONFIRMED finding → GitHub issue URL appears in findings table → Slack notification fires
- No GitHub connection → POST /scan returns 401 → UI shows "Connect GitHub first"
- Target repo with issues disabled → issue_filed: false in finding → UI shows "filing failed" badge

## Edge Cases
- Semgrep not installed → scan_step raises FileNotFoundError → workflow fails → UI shows error state
- Repo with zero high/critical findings → findings[] empty → UI shows "No high/critical findings" empty state
- Sonnet 4.6 returns empty response → scanner falls back gracefully → finding marked UNVERIFIABLE
- E2B timeout (30s) → verdict = UNVERIFIABLE → scan continues to next finding
- GitHub 429 rate limit → retries once after retry-after seconds → if still 429, issue_filed: false
- SSE client disconnects mid-scan → server-side cleanup runs (remove_queue) → scan continues in DBOS
- Workflow crash mid-verify → DBOS replay → _ensure_repo re-clones if tmpdir missing → scan resumes
- max_files=5 cap → only 5 findings verified → findings_truncated: true in response

## Critical Paths
1. Full CommitGuard scan end-to-end: POST scan → DBOS workflow runs scan+verify+file → findings with GitHub issue URL
2. Crash recovery: crash mid-verify → DBOS replay → scan completes from last step
3. Auth gate: POST scan with no GitHub token → 401, not a crash
4. SSE job scoping: stream only yields events for the subscribed job_id
