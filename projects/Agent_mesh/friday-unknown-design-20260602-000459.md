## Problem Statement
Solo founders running complex 24/7 AI agents currently rely on fragile infrastructure like in-process asyncio queues, which lose state on crashes, or piece together multiple fragmented SaaS tools. Building a robust orchestration engine from scratch wastes valuable product-building time.

## Demand Evidence
The founder is personally losing hours a week babysitting agents and fixing crashes manually.

## Status Quo
Manually monitoring and restarting agents, losing in-flight task state during crashes, leading to lost productivity and unreliable agentic systems.

## Target User & Narrowest Wedge
Solo AI founders and engineers. The narrowest wedge is a lightweight Python CLI (`agent-mesh init`) that generates a local DBOS + Postgres setup featuring a pre-wired, durable 3-pass (plan-execute-review) base agent class.

## Constraints
- Must be easy to adopt for solo founders (zero new infrastructure beyond Postgres).
- Must guarantee execution durability.
- Must decouple orchestration from specific LLM models.

## Premises
1. Building a custom asyncio+Redis+Dramatiq fallback is a waste of time when DBOS gives you durability with just Postgres. We should start directly with DBOS.
2. The real product isn't the orchestration engine (which is off-the-shelf DBOS), but the pre-wired 3-pass (plan-execute-review) agent loop.
3. To sell this to other solo founders, this must be a deployable starter kit or CLI tool (`agent-mesh init`), not just a repo they have to manually configure.

## Approaches Considered
### Approach A: The DBOS CLI Starter Kit
A Python CLI (`agent-mesh init`) that generates a local DBOS + Postgres setup with a pre-wired 3-pass base agent class.
### Approach B: The Firecracker-First Appliance
A Docker Compose stack combining DBOS/Postgres with a local Firecracker microVM pool (or E2B integration) for immediate secure code execution.
### Approach C: The Cloudflare-Native Edge Mesh
Ditch DBOS/Postgres and build the starter kit entirely on Cloudflare Workflows + Durable Objects.

## Recommended Approach
Approach A: The DBOS CLI Starter Kit. It ships the fastest, provides immediate durable orchestration value, and has the lowest adoption friction for the target audience.

## Open Questions
- What is the easiest way to package the DBOS setup so it runs seamlessly on a user's machine?
- How should we structure the DBOS workflow so that users can easily extend the 3-pass loop with their own tools?

## Success Criteria
- A user can run `agent-mesh init` and have a working, crash-proof 3-pass agent loop running against DBOS locally in under 5 minutes.

## Distribution Plan
Python Package Index (PyPI) as a CLI tool (`pip install agent-mesh`).

## Dependencies
- DBOS Transact library
- Pydantic
- Click (for CLI)
