# Agent Mesh Multi-Agent Test Plan
Generated by /autoplan (Phase 3: Eng Review)

## 1. Codepaths & Coverage Map

| Codepath/Flow | Test Type | Current Coverage | Goal/Gap |
|---------------|-----------|------------------|----------|
| `agent-mesh init` scaffold generation | Unit (FS Mock) | Basic | Ensure idempotency and collision handling |
| Docker/DBOS Pre-flight checks | Unit (Mock `psycopg2`) | Missing | Test `DockerNotRunningError` and DB timeout |
| Researcher Agent Step (LLM Call) | Unit (Mock LLM) | Missing | Verify standard schema return & DBOS step bounds |
| Coder Agent Sandbox Execution | Integration | Missing | Verify restricted Docker environment & timeouts |
| Multi-Agent Handoff & Validation | Unit/Integration | Missing | Force `ValidationError` and assert the LLM retry loop |
| Postgres State Corruption | Fault Injection | Missing | Kill DB mid-workflow; assert DBOS perfectly resumes |

## 2. Testing Strategy
- **Network Isolation:** All unit tests for DBOS steps involving LLM calls MUST bypass the network using mocked responses. This ensures deterministic state machine transition testing.
- **Resilience:** The LLM schema validation error path is the most critical. Tests must explicitly simulate a malformed JSON string from the LLM and verify the workflow feeds it back as a retry prompt up to 3 times before finally raising an exception.

## 3. Required Evals
- **Schema Adherence Eval:** Run 50 prompt iterations of the Researcher -> Coder handoff to ensure the system prompt enforces the expected schema reliably across different queries.
