## Affected Pages/Routes

- `/ui` Agents — roster loading, agent launch, validation, backend errors, and killswitch blocking.
- `/ui` Workflows — newest-first workflow listing, selection, inspector, tasks, and lifecycle actions.
- `/ui` Activity — canonical SSE events and connection/reconnection state.
- `GET /api/agents` — registered agent payload.
- `POST /api/agents/:agentId/run` — real workflow ID, unknown agent, and killswitch response.
- `GET /api/agents/events` — canonical event stream and reconnect behavior.
- `GET /api/agents/killswitch` — current state.
- `POST /api/agents/killswitch/engage` — engage with reason.
- `POST /api/agents/killswitch/release` — release.
- `GET /api/workflow/search` — pagination, ordering, filters, and newly created workflows.
- `GET /api/workflow/:workflowId` — workflow and ordered task detail.
- `PUT /api/workflow/:workflowId/pause` — valid and invalid transitions.
- `PUT /api/workflow/:workflowId/resume` — valid and invalid transitions.
- `POST /api/workflow/:workflowId/retry` — valid and invalid transitions.

## Key Interactions to Verify

- Launching an agent creates exactly one workflow and opens that workflow.
- The returned workflow ID is a persisted workflow ID, never a placeholder.
- Live events are associated with the active workflow.
- Selecting a workflow opens the right-side inspector.
- The inspector becomes a full-screen sheet at narrow viewport widths.
- Pause, resume, and retry disable duplicate submission and refresh detail.
- Engaging the killswitch visibly changes global state and blocks new runs.
- Releasing the killswitch permits a subsequent run.
- Reconnecting SSE preserves displayed events and refreshes durable workflow state.

## Edge Cases

- Empty agent and workflow lists.
- Backend offline, timeout, non-JSON errors, NestJS message arrays, and empty success responses.
- Malformed agent, workflow, task, killswitch, and SSE payloads.
- Agent removed between roster load and launch.
- Killswitch engaged between dialog open and submission.
- Double-click or rapid repeated workflow mutations.
- Workflow status changed by another request before an action completes.
- Workflow not found after selection.
- Event received before workflow detail resolves.
- Disconnect during an active run.
- Pagination boundary, duplicate timestamps, unknown status, and large workflow list.
- Component unmount or selection change while a request is pending.

## Critical Paths

1. Start the real SQLite-backed server with deterministic injected AI behavior.
2. Open `/ui`, navigate to Agents, and launch a seeded agent.
3. Verify a persisted workflow ID is selected.
4. Observe at least one canonical event for that workflow.
5. Open the workflow inspector and verify ordered tasks.
6. Pause and resume the workflow.
7. Retry an eligible failed workflow.
8. Engage the killswitch and verify a new run returns a visible `503` error.
9. Release the killswitch and verify a new run succeeds.
10. Disconnect and reconnect SSE, then verify workflow state is reconciled.
