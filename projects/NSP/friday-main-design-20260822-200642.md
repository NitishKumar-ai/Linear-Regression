## Problem Statement

A first-time student on a phone cannot finish a National Scholarship Portal application and know what happens next in one sitting. Today's [scholarships.gov.in](https://scholarships.gov.in/) makes them hunt schemes, survive Aadhaar/document/INO failures, then sit in a status black hole. This prototype is an independent hackathon rebuild: five facts, a curated mock catalog, apply to every match without picking schemes, then a shareable receipt that tells the truth. Target clip: about two minutes. Deadline: 28 August 2026, 8:00 PM IST.

The person in the video is a Class 12 first-time applicant on their own phone. We did not interview a named student. **Priya** is a shooting fixture, not a real person.

"One tap" means the student does not pick schemes. The UI still has two citizen actions after facts: **Apply to all matches** (goes to confirm) then **Submit N applications**.

## What Makes This Cool

The student does not pick schemes. They answer five facts. We show every mock match, including misses. Submit fans out to all matches. The whoa is the receipt: several application rows, institute verification named as a wait, one recoverable mock failure with a next step.

10x (not this week): Hindi/vernacular, WhatsApp parent forwarding, voice fill. v1 already has a shareable receipt URL (copy the link, or select it if clipboard fails). That is not the 10x WhatsApp product.

## Premises

Agreed 2026-08-22:

1. The problem is not "NSP looks old." It is finish-apply-and-know-the-next-step in one sitting.
2. Citizen journey is facts → mock matches → apply to every match → per-scheme status. Scheme browsing is out.
3. Identity, documents, OTP, bank, INO, PFMS are mocked and labeled. No live NSP. OTP is not a v1 screen. Aadhaar never appears as a number; only a labeled mock boolean `aadhaarSeeded` on the locker.
4. "Two minutes" is the hero path with a complete mock locker. Missing-doc and zero-match are real on-screen branches, not minute one of the video.
5. This week is four phone screens. Hindi/parent-voice are 10x. Status honesty is v1. Recovery stays on screen 4 (inline), not a fifth route.
6. Codex is the required build contribution. No in-app chatbot. No "Why these N?" extra button.

## Landscape (why not a matcher-only demo)

Conventional civic-tech redesigns treat the wound as discovery. NIC already claims NSP suggests eligible schemes. Public 2026 student writeups are about Aadhaar, uploads, institute nodal officers, PFMS/bank mismatches, and dead status pages. EUREKA: a prettier matcher is an incumbent feature. Apply-to-every-match only whoas if submit and honest status ship.

### Types

```ts
type ClassYear = '10' | '11' | '12' | 'ug1'
type State = 'KA' | 'MH' | 'OTHER'
type Category = 'GEN' | 'OBC' | 'SC' | 'ST'
type IncomeBand = 'under_1l' | 'under_2_5l' | 'under_8l' | 'above_8l'
type InstituteType = 'gov_school' | 'gov_pu' | 'private_pu' | 'gov_college' | 'private_college'
type SchemeId = 's01' | 's02' | 's03' | 's04' | 's05' | 's06' | 's07' | 's08' | 's09' | 's10' | 's11'
type Presence = 'present' | 'absent'

type Facts = {
  classYear: ClassYear
  state: State
  category: Category
  incomeBand: IncomeBand
  instituteType: InstituteType
}

type Locker = {
  displayName: string
  incomeCert: Presence
  categoryCert: Presence
  marksheet: Presence
  bankLast4: string
  ifsc: string
  mockBankName: string
  pfmsBankName: string
  aadhaarSeeded: boolean
  religion: string | null
  gender: 'F' | 'M' | null
  singleGirlChild: boolean
  udid: Presence
}

type Session = {
  facts: Facts
  fixtureId: 'priya' | 'missing-doc' | 'zero' | null
  locker: Locker
}

type ReceiptV1 = {
  v: 1
  fixtureId: Session['fixtureId']
  facts: Facts
  locker: Locker
  applications: { id: SchemeId; status: 'submitted' | 'action_needed' }[]
}
```

`sessionStorage` key `nsp.session` holds `Session`. Missing session on `/matches` or `/confirm` redirects to `/`.

Religion is "set" iff `religion != null && religion !== ''`. UDID is present iff `udid === 'present'`. GENERIC uses `religion: null`, `gender: null`, `udid: 'absent'`. Encode keeps JSON `null`. Do not omit those keys.

No Aadhaar. No password.

Controls:

- **See matches** — enabled iff all five facts set. Writes `{facts, fixtureId: null, locker: GENERIC_LOCKER}`, goes to `/matches`.
- **Use demo profile (Priya)** — writes Priya session, goes to `/matches`.
- **Try missing documents** — writes missing-doc session, goes to `/matches`.
- **Try zero matches** — writes zero session, goes to `/matches`.

### Screen 2 — `/matches`

Shows all 11 catalog rows: matched first (`id` asc), unmatched after (`id` asc). Each row uses `reasonMatch` or `reasonMiss` from `schemes.json`.

**Apply to all matches** enabled iff `matchedCount >= 1`. Goes to `/confirm`. N for later submit = `matchedCount` (Priya: 6), including the row that will be `action_needed`.

Copy on this screen: "Some schemes also use the mock locker (religion, UDID, single-girl). You did not type those. They are simulated."

Zero matches (`fixtureId: 'zero'`): CTA disabled, copy "No mock schemes match these facts." **Change answers** is a link to `/` on every `/matches` screen (Priya, missing-doc, zero, manual).

### Screen 3 — `/confirm`

Visible locker rows only: income cert, category cert, marksheet, bank last-4, IFSC, mock bank name, Aadhaar-seeded (labeled boolean). Other locker keys are data, not rows.

Each scheme has `requiredDocs: ('incomeCert' | 'categoryCert' | 'marksheet')[]`. Confirm ORs required docs of the **matched** set. Matcher does **not** use required docs. Missing matcher field → unmatched. Missing required doc → still matched, Submit disabled.

Submit enabled only if every required doc in that OR-set is `present`. Missing-doc: name the gap (Priya missing-doc: "Previous marksheet (mock) missing"), Submit disabled. Primary escape: **Use complete mock locker** (same facts, Priya locker with `marksheet: 'present'`). Then Submit enables. Secondary: **Back to facts**.

**Submit N applications** → `POST /api/mock/submit` with JSON body `Session`. Success: `200 { token }`, client `router.push('/a/' + token)`. Failure: stay on `/confirm`, labeled "Mock submit failed. Retry." Retry POSTs the same `Session` with no `forceFail`.

Tests may POST `{ ...session, forceFail: true }` (`forceFail` is not on `Session`; the route reads it as an extra key). That returns 503. The hero path never sets it.

POST is first-submit only. Server ignores any client-built `applications` array. It runs `firstSubmit(session)`:

1. Match scheme ids with `matching.ts`.
2. For each matched id, `status = (id === 's06' && fixtureId === 'priya') ? 'action_needed' : 'submitted'`.
3. Return `ReceiptV1` (`v: 1`, session fields, those applications).
4. Encode token. Do not persist elsewhere.

Resubmit never POSTs.

### Screen 4 — `/a/[token]` receipt

Receipt = matched applications only. No unmatched ids. No `not_sent`.

Status subcopy:

- `submitted`: `Institute verification pending · ~5–12 days (simulated)`
- `action_needed`: `Mock bank name does not match PFMS · fix and resubmit this one`

**Recovery (Priya s06 only):** inline field pre-filled `Priya S`. **Resubmit this one** enabled iff the field equals `pfmsBankName` (`Pria S`). On success: set `locker.mockBankName` to that value, set s06 to `submitted` (institute subcopy), hide editor, canonical-encode, `router.replace`. Old URLs stay pre-recovery. Do not POST again. Copy should not pretend PFMS is the legal name source; it is a simulated mismatch.

Copy status link: clipboard plus visible selectable URL.

Unknown / corrupt token: labeled mock 404, back to `/`.

### Token schema (the only store)

`ReceiptV1` is defined above. Scheme names and type chips are **not** in the token; join from `schemes.json` by `id`. `applications` is the matched set only.

`token = base64url(utf8(JSON.stringify(canonical(receipt))))`.

`canonical(value)`: recursively sort object keys. Keep `null`. Drop only `undefined`. `applications` sorted by `id`. Manual receipts include `"fixtureId": null`, `"religion": null`, `"gender": null`. Do not omit those keys.

POST encode is **deterministic**: same canonical session JSON → same token. That is not HTTP idempotency. There is no server store to dedupe.

GET `/a/[token]` decodes or 404s. Payload is full `ReceiptV1` (~647 utf8 bytes / ~863 token chars for Priya first-submit). Under ~2k.

Citizen code never fetches `*.gov.in`. The only network call is same-origin `POST /api/mock/submit`.

### Honest scale and safety

This is a mock. A real NSP would keep receipts in a ministry system of record, INO as a human SLA, PFMS as a bank rail, and Aadhaar as UIDAI. We will not build those. Path to scale: replace `src/lib/mocks/` with approved public sandboxes if they ever exist; keep the four citizen screens; keep receipt URLs secret; keep INO out of the citizen UI. Token leakage of mock Priya is acceptable; leakage of real PII is not.
